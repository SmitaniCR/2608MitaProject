# 保守者向けメモ(スキル本体を更新する人へ)

このファイルは学習者とのセッション中には参照しない。`SKILL.md`や
`references/curriculum-template.md`自体を編集する人(スキルの保守者)向けの規定を
まとめる。

## `template-version`の更新ルール

`references/curriculum-template.md`を変更したら`template-version`を必ず更新する
(Stepの追加・削除、前提Stepの変更、完了条件の変更など、学習者のCURRICULUM.mdに反映される
べき変更が対象。誤字修正のみなら据え置いてよい)。更新しないと既にコピー済みの学習者に
案内が届かない。

## 新しいStepを追加する際のチェックリスト

Step追加は「既存の別箇所からの参照更新を忘れる」追随漏れが起きやすい。最低限以下を確認する。

1. `curriculum-template.md`内の**目次・修了基準・依存関係マップ(mermaid)**の3箇所を
   同時に更新したか。
2. Step0チェックリストの「促す先」列を見直し、新Stepが該当概念の自然な実証機会になって
   いないか確認する。該当すれば追記する。**そのとき、必須Stepで必ず来る機会なら
   「対象外」「会話で確認済み」への緩和は原則不要、題材や任意Step次第で来ないことが
   ありうるなら緩和を残す**。
3. **`grep -n 'Step[0-9]' SKILL.md`(または同等の全文検索)の全ヒットを1件ずつ確認し
   更新したか**。「Step番号の範囲を書いている箇所を探す」だけでは、「Step20・Step24・
   Step27」のような**列挙(範囲ではない)形式の記述を見落とす**(実際にこの見落としで
   新領域Stepのリストが2箇所とも古いまま残った事例がある)。範囲・列挙を問わずStep番号を
   含む行を機械的に洗い出すこと。`README.md`も検索対象に含める(Step数・Step範囲の
   記述が古くなりやすい)。
4. 前提Stepの変更によって、既存Stepの前提記述やmermaid図の矢印との整合が崩れていないか。
   **技術的な前提(実線`-->`)と推奨順のみ(点線`-.->`)の区別も忘れずに揃える**
   (詳細は`curriculum-template.md`冒頭の説明参照)。
5. **新Stepに一意の`id`(kebab-case、例: `sql-native-query`)を採番し、見出し行末に
   `<!-- id: xxx -->`として付けたか**。既存idと重複しないこと。
6. 上記のいずれかを変更したら`template-version`を更新したか。

Step0チェックリストの**項目数**を増減させた場合は、上記に加えて`SKILL.md`**と
`curriculum-template.md`の両方**で「16項目」「n/16」のように項目数を直書きしている
箇所(モード0・5の表示例、修了基準の文言等)を検索し、`n/全項目数`のような相対表現に
直っているか確認する(`curriculum-template.md`自身の修了基準にも直書きが残っていた
実例があるため、`SKILL.md`だけの確認では不十分)。

## idの運用ルール

- **Step番号**(「Step12」等): 表示用ラベル。追加・分割・並べ替えに応じて**自由に変更してよい**。
- **id**(`<!-- id: xxx -->`): 一意で、**一度割り当てたら変更しない**。学習者のPROGRESS.mdは
  idで完了状態を管理するため、番号が変わっても完了記録は失われない。

番号を振り直した場合は、`curriculum-template.md`内の目次・修了基準・mermaid図・各Stepの
前提Step記述に残る古い番号を揃えて更新する(`grep`で`Step\d+`を検索する)。

**既存Stepを分割・統合する際**:

1. 元の学習内容を主に引き継ぐ側のStepには**元のidをそのまま使う**(完了記録の引き継ぎ)。
2. 新たに切り出した側には**新しいidを採番する**。
3. 分割は初期化ロジックのid比較で通常のテンプレート更新案内として学習者に伝わる。
   分割用の特別な案内文は不要。
4. Step0チェックリスト項目の分割も同様。
5. 反映後、目次・修了基準・依存関係マップ・`template-version`を通常のStep追加と同じ手順で更新する。
